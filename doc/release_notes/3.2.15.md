## LaueTools 3.2.15 — Release notes

### ⚠️ Changes in behaviour
- **`lauetools-copy` copies the notebooks into subfolders.** It used to copy only the `scripts_*.py` files, directly in the destination folder. It now writes `notebooks/`, `tutorials/` and `scripts/` subfolders (see New features). The default destination is `./lauetools_examples` instead of the current folder.
- **Files of `lauetools-copy` are never overwritten.** Notebooks or configuration files already present in the destination folder (that you may have edited) are kept. Use `--force` to overwrite them.
- **Example images are no longer in the git repository.** `AH12_CMT_r14_0003.tif` to `_0005.tif`, their `.psp` and `.dat` files and the `Mg_nlut3`, `Mg_nlut4` and `Ti_nlut4` `.angles` files were removed. The example images are downloaded with `lauetools-copy --download`.

### New features
- **New notebook `quickstart/laue_maps_quickstart.ipynb`:** complete analysis of a 2D map of Laue patterns recorded at BM32, for new users, with one settings cell (minimum: `RAW_DATA_FOLDER` and `KEY_MATERIAL`).
  1. Choose a map in the list of the scans of the experiment (BLISS `.h5` file of `RAW_DATA`).
  2. The settings files `peaksearch.yaml` and `indexing.yaml` are written in `PROCESSED_DATA/.../configs/`. The calibration `.det` file is found automatically, and the values of a `.psp` file of the LaueTools GUI can be imported with `PSPFILE`.
  3. Peak search: test on one image with a plot, then all images.
  4. Indexation and refinement: test on one image, then all images.
  5. Maps: quality of the indexation, orientation (IPF colours), grains, KAM and GROD.
  6. Optional: the same analysis for a series of maps (e.g. temperatures).
  - Computations run on the ESRF cluster (SLURM: `magnifix` for large jobs, otherwise `hpc6/7/8`) when `sbatch` is available, for example on jupyter-slurm.esrf.fr. Otherwise they run on the current computer with all its CPUs (`EXECUTION = 'auto'`).
  - Safe to run again: steps already done are reloaded, not computed again (`REDO = True` to compute them again). Images are only read, and results are written in `PROCESSED_DATA` (or `OUTPUT_ROOT`).
- **New notebook `peaksearch/peaksearch_map.ipynb`:** peak search of a map driven by one YAML configuration file per experiment (images → `.dat` and `.cor` files). It replaces `PeakSearch_MultiProcessing.ipynb` (same `readmccd.PeakSearch`, all parameters in the configuration file).
  - Test on one image with a plot of the peaks found, then a batch run locally or on the ESRF cluster (`EXECUTION = 'slurm'`; partition magnifix, hpc6/7/8, nice or auto).
  - The last cell writes the configuration file of the indexation, the input of `indexation/1_index_refine.ipynb`.
  - Without notebook: `python -m LaueTools.peaksearch_batch --config configs/my_experiment.yaml --ncpus 64 [--image-range 0 999]`.
  - Examples: `configs/ma6034_Zn.yaml` (sCMOS) and `configs/a321220_MgO_Fe_1000.yaml` (EIGER 4M, parameters imported from a `.psp` file).
- **New modules:**
  - `peaksearch_batch.py`: configuration, peak search of one image, multiprocessing and SLURM jobs for a series of images.
  - `map_workflow.py`: the steps of the quickstart notebook (`list_maps`, `scan_info`, `make_configs`, `run_step`, `quality_maps`, `orientation_maps`, `segmentation`, `process_maps`), using `peaksearch_batch` and `indexing_batch`.
- **Configuration files without editing YAML by hand** (`indexing_batch` and `peaksearch_batch`):
  - `new_config(newfile, template=None, **changes)` creates a configuration from `config_template.yaml` or from the file of another experiment. Parameters are given by name, whatever their section; a misspelled name raises an error.
  - `save_config(cfg, newfile, params=...)` saves the parameters changed during a test on one image. The comments of the original file are kept.
  - `peaksearch_batch.import_pspfile(cfg, 'my.psp')` writes the parameters of a `.psp` file of the LaueTools GUI in the configuration.
- **Large maps: `.dat`, `.cor` and `.fit` files in subfolders** of n files (`images_0_9999/`, `images_10000_19999/`, ...):
  - Peak search: `output: nbfiles_per_folder: n`. Indexation: `scan: nbfiles_per_folder` (copied automatically by `indexing_config()`), and `output: fit_subfolders: true` to write the `.fit` files in the same subfolders.
  - The `.fit` file readers (`fitfilereader`, `orientationclustering`) and the notebooks `2_postprocess_maps` and `3_segmentation_grains` read the subfolders (`IB.fitfiles_layout(cfg)`, `IB.corfile_path(cfg, i)`, `IB.fitfile_path(cfg, i, grainindex)`).
- **Indexation notebooks: refine each grain again** (`3_segmentation_grains.ipynb`, new optional sections):
  - Each grain (cluster of orientations) is refined again at its map points, starting from its own UB matrices: orientation check and refinement only, no indexing from scratch (`grain_refinement_tasks`, `refine_grains`).
  - Optional second refinement with a fixed set of reliable reflections per grain (`grain_spots_selection`). Spots are selected by quality (`spot_quality`: deviation, elongation, fwhm, isolation, pixel deviation), and the same reflections are used at all points of the grain (`reference_reflections`).
  - Runs in the jupyter session or as a SLURM job (`prepare_slurm_grain_job`, `load_slurm_grain_results`).
  - New example configurations: `a321220_MgO_2grains.yaml` and `a321220_MgO_Fe_1000.yaml`.
- **Orientation and cluster maps oriented with the sample motors:** cluster maps can be transposed so that the y motor (yech, yps, sy) is vertical, with motor names as axis labels (same convention as Mosaic & Monitor in 3.2.14). The helpers `map_transposed()` and `map_axes_labels()` moved to `generaltools`.
- **`lauetools-copy`: copy the notebooks after `pip install`.**
  - `lauetools-copy -d my_folder` copies the quickstart, peak search and indexation notebooks with their YAML configuration files (in `notebooks/`, with their relative paths), the older tutorial notebooks (`tutorials/`) and the scripts (`scripts/`).
  - `-w notebooks tutorials scripts images` copies only part of them.
  - `--download` also downloads the example images (files of the GitHub release `examples-data`) to `my_folder/LaueImages`. Files already downloaded are skipped. `notebooks/download_examples.py` does the same.
  - New command `lauetools-copy-gui`: the folder is chosen in a dialog, no terminal needed. On Windows it is an `.exe` without console window.
- **`scripts/notebook_to_html.py --publish`** writes, in one step, the two versions of a notebook to commit: `<name>.html` (anonymized, with outputs) and `<name>.ipynb` (anonymized, without outputs; `--keep-outputs` keeps the text outputs).
  - The working notebook is kept as `<name>.local.ipynb` (ignored by git): run and edit this one, then publish it again.
  - The anonymization rules `anonymize_rules.local.yaml` are found automatically in the folder of the notebook or in its parent folders.

### Performance
- **Multiprocessing in jupyter notebooks:** pools of worker processes started from a notebook use the `forkserver` start method (`generaltools.mp_context()`). Forking the jupyter kernel could leave the pool stuck forever, or make each later process start wait about 20 s. Scripts and SLURM jobs keep the default method.

### Fixes
- **sCMOS peak search with band removal** (`readmccd.PeakSearch`, `CCDLabel='sCMOS'`, `npixels > 0`): the peaks in the detector bands were removed from an undefined array. They are now removed from the peak list and from the max intensities.

### Packaging
- **Smaller sdist:** jupyter checkpoints (`.ipynb_checkpoints`, which kept copies of notebooks with their outputs), personal notebooks (`*.local.ipynb`, `Untitled*.ipynb`, `*_jsm.ipynb`), SLURM logs and test `.fit` files are excluded. The sdist built from a working copy goes from 54 MB to 13 MB; the wheel is 6.4 MB.
- **`exclude-package-data` works again:** its key was `lauetools` instead of the package name `LaueTools`, so nothing was excluded.
- **New package data:** the quickstart and peak search notebooks, with their README and YAML configuration files.

### Repository
- **Notebooks without outputs:** `quickstart/laue_maps_quickstart.ipynb`, `peaksearch/peaksearch_map.ipynb` and the 3 indexation notebooks are committed anonymized and without outputs (from 7.7 MB to 136 KB). Their HTML versions keep the outputs, with anonymized texts and paths in figures hidden.

### Known limitations
- **Example images:** `lauetools-copy --download` needs the GitHub release `examples-data`. Until it is published, the command prints that the release was not found.
- **Tutorial notebooks** (`tutorials/`) look for images in the `LaueImages` folder of the installed package. They do not yet find the images downloaded in `my_folder/LaueImages`.
- **Notebooks using `/data`:** the example configurations of the quickstart, peak search and indexation notebooks need access to the ESRF `/data` file system.
