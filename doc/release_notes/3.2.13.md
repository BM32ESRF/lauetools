## LaueTools 3.2.12 — Release notes

### ⚠️ Changes in behaviour
- **Mosaic & Monitor results are written in the image folder by default.**
  - Results files (`.h5`, maps and profiles as text) and the new optional `.png` plots all go into the folder chosen in the new *Output* group: image folder (default), PROCESSED_DATA mirror folder, or any folder.
  - If the chosen folder is not writable, the PROCESSED_DATA mirror folder is used, then `~/lauetools_results`. The panel shows the folder actually used.
  - Some files were written in the folder where `lauetools` was started; this no longer happens.
- **Maps are oriented with the sample motors.** The y motor (yech, yps, sy) is now vertical and the x motor (xech, xps, sx) horizontal. *Transpose Map* is set automatically from the BLISS command: the fast motor is the first motor of `amesh`/`dmesh` and the second one of `fscan2d`. You can still change it by hand.
- **Position Centroid (parallel computation)** uses the minimum intensity of the ROI as baseline. The former code subtracted the maximum. *GUI (sequential)* mode keeps the former computation.
- **Map plots:** pixel values below 1 are clipped only in mosaic plots. Before, all maps were clipped, which flattened, for example, peak displacements smaller than one pixel.
- **Colour scale of result plots:** vmin and vmax are now absolute data values, set with a range slider (see below). They are kept when you change the colormap or switch to Log scale.
- **ssh sessions:** LaueTools disables D-Bus when it runs in an ssh session without a graphical session (see Performance). Set `LAUETOOLS_KEEP_DBUS=1` to keep it.

### New features
- **Parallel computation of all Mosaic & Monitor counters** (PeakSearchGUI):
  - Mosaic, mean, max, peak to peak, centroid, fitted peak position, amplitude, displacement and size are all computed in parallel. Before, only the mosaic of the 'All' selection was.
  - This works with every image selection mode: All, start/last/step, rectangle and ROI.
  - **Run on:** the local machine (computed in the GUI session, which stays responsive) or a SLURM partition (magnifix, ub20, nice hpc6/hpc7/hpc8). The default number of CPUs is 64 locally and the partition size for SLURM.
  - **Cancel** button, progress gauge in the panel, and a progress bar in the terminal.
  - **Save results files** and **Save plots (.png)** options. With nothing saved, nothing is written on disk.
  - *GUI (sequential)* keeps the former computation.
- **New workflow `workflows.ROICountersWorkflow`:**
  - Counters: `mosaic`, `mean`, `max`, `ptp`, `sum`, `pixelval`, `XYmax`, `XYcentroid`, and `fit` (2D gaussian).
  - Works on one or many ROIs over a set of images, processed in parallel. Results are saved in `.h5` (`save_results`, `load_results`).
  - Missing or unreadable images give NaN.
- **New module `scripts/workflowlauncher.py`** runs the same workflow from the GUI, a notebook or the command line:
  - `python -m LaueTools.scripts.workflowlauncher run config.json --ncpus 32`
  - `python -m LaueTools.scripts.workflowlauncher submit config.json --resource magnifix --wait`
  - `python -m LaueTools.scripts.workflowlauncher resources`
  - From a notebook: `WL.launch(config, resource=...)`, then `job.wait()` (with a progress bar) and `job.results()`.
  - SLURM jobs are submitted with `sbatch`, through ssh on a submit host if `sbatch` is not available locally (`LAUETOOLS_SLURM_SUBMIT_HOST`, default `cluster-access`).
  - Jobs are followed through a status file on `/data`.
  - Computing resources can be completed in `~/.lauetools/computing_resources.json`.
  - `output_folder(imagefolder, mode)` applies the same output folder rules as the GUI.
- **Stacked EIGER images:** BLISS/LIMA hdf5 files with several frames are supported.
  - The detector label is detected automatically (`EIGER_4MCdTe` or `EIGER_4MCdTestack`).
  - Images are browsed with a global image index across files.
  - Frames not yet recorded during a running scan are detected.
  - The last recorded image and the BLISS command are shown in the browse and Mosaic & Monitor panels.
- **Result plot windows:**
  - The plotted quantity (e.g. "max intensity in ROI", "fitted peak X position (pixel)") is shown in the title and as colour bar label.
  - Motor names label the map axes, and 1D profiles have axis labels.
  - **New two-thumb range slider (`GUI/rangeslider.py`)** with a value field on each side replaces the separate min/max sliders and fields. You can drag a thumb or the whole interval, click to move the nearest thumb, double-click to select the whole range, or type values.
  - *File > Save* opens a save dialog in the output folder.
- **New notebook `PixelMonitoring_Workflow.ipynb`**, with its HTML version: ROI counters and mosaic from a BLISS logfile scan, computed in the kernel, as a local job or on SLURM.
- **`scripts/notebook_to_html.py`:**
  - **`--strip`** writes the notebook anonymized and without outputs (the version to commit). The original is kept as `<name>.local.ipynb`, which git ignores.
  - **`--mask CELL:Y0-Y1`** hides rows of saved figures, for example a path in a title.
  - Interactive widgets without a saved image are labelled as an interactive figure or a progress bar.

### Performance
- **GUI start-up in ssh sessions:** GTK waited 25 s for the desktop portal at each GUI start, for example on lbm32gpu1. The main window now opens in about 8 s instead of about 32 s.
- **Mosaic & Monitor:** a 676-image map with all counters takes about 4 s with 32 to 64 CPUs, against 72 s in sequential mode.

### Fixes
- **Peak Displacement vector plot no longer crashes:** its colour normalization was an unfinished placeholder (`...`).
- **`UseCaseHandler` DAXM and ascan ROI counters:** they called a `ROICountersWorkflow` class that did not exist. It now exists.
- **Workflow configuration with `listindices=range(...)`:** the range was written as a string in the json file. It is now written as a list of indices.
- **LUT selector:** shows the colormap name instead of `<matplotlib.colors...>`.

### Repository
- **Notebooks without outputs:** `PixelMonitoring_polycrystalsMgO_Sept2026.ipynb` and `Indexation_MultiProcessing-Tutorials.ipynb` are committed without outputs and anonymized. Their HTML versions keep the outputs, with anonymized texts and paths in figures hidden.
- **Removed files:** 200 `testZrO2_*_g0.fit` test files, SLURM logs and unused notebooks (`Untitled*.ipynb`, `test_backreflectiongeometry.ipynb`, pnCCD tests). These test files and SLURM logs are now ignored by git, as are `*.local.ipynb` and `*.local.yaml`.
- **CI:** the pytest step was removed from the GitHub workflow.

### Known limitations
- **SLURM from lbm32gpu1:** submission needs ssh to the submit host (`cluster-access`) without a password. It has not yet been tested end to end from lbm32gpu1.
- **Displacement vector window:** it has no colour bar.
- **Other plot windows:** the older `ImshowFrame_Scalar` window and the plot windows of other GUIs keep their former vmin/vmax controls.
