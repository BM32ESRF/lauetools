## LaueTools 3.2.18 — Release notes

### ⚠️ Changes in behaviour
- **Peak search writes only `.cor` files when a detector calibration is given.** The `.cor` file contains all the peak properties of the `.dat` file (and 2θ, χ). The `.dat` file is still written without calibration, or with `write_dat: true` (section `output:` of the peak search YAML configuration) (`peaksearch_batch`, quickstart notebook), or `WRITE_DATFILE = True` in the `PeakSearch_MultiProcessing` notebooks.
- **New file dialog to open files.** The dialogs opening an image, a peak list or a materials file (main GUI, peak search, peak list and detector calibration boards) are a `FastFileDialog`: it reads only the file names, so it opens at once in folders of tens of thousands of files, where the GTK dialog took minutes. The system dialog is opened by its *Browse...* button, and is still used for saving and for multiple selection. Set `LAUETOOLS_SYSTEM_FILEDIALOG=1` to always use the system dialog.
- **D-Bus in ssh sessions.** It is no longer always disabled in a remote session (ssh with X11 forwarding): it is disabled only if the desktop portal does not answer within 2 s. The GTK file dialogs need it for their *Recent* place. Set `LAUETOOLS_KEEP_DBUS=1` to always keep it, or `LAUETOOLS_DISABLE_DBUS=1` to always disable it in remote sessions.
- **`PixelMonitoring_Workflow` notebook: section 3a saves its results.** Results computed in the kernel are written in `roicounters_<hash>.h5` in the output folder (`OUTPUT_FOLDER_MODE`), and loaded instead of computed again when the parameters are the same (`RECOMPUTE = True` to compute again).
- **`PeakSearch_MultiProcessing` notebooks are anonymized.** Data paths, proposal numbers and sample names of `PeakSearch_MultiProcessing`, `PeakSearch_MultiProcessing_Tutorials` and `PeakSearch_MultiProcessing_april2025` are replaced by placeholders such as `<proposal>` or `<inhouse path>`: set your own paths before running them.

### New features
- **Indexing of a map guided by its neighbours** (`indexing_neighbours.py`, `usepreviousUB: neighbours` and section `neighbours:` of the indexing YAML configuration, notebook `indexation/1d_index_refine_neighbours.ipynb`). Checking and refining a UB matrix that already indexes a neighbouring point takes seconds, whereas indexing from scratch takes minutes per image for large unit cells.
  - A seed pass indexes from scratch a grid of points, rectangular or hexagonal, every `seed_step` points or every `seed_spacing` microns.
  - Every other point then checks the UB matrices of its indexed neighbours (within `radius`), and is indexed from scratch only if none is accepted.
  - The UB matrices are shared through files, so the processes of one machine and the jobs on several SLURM nodes can work on the same map.
- **Indexing workflows with the `.fit` files of a previous indexation** (`map_workflow.indexing_workflow()`, `INDEXING_WORKFLOW` of the quickstart notebook):
  - `scratch`: every point indexed from scratch.
  - `refine`: UB matrices of the previous `.fit` files refined only.
  - `refine_or_scratch`: previous UB matrices refined, indexing from scratch if they are rejected.
  - `matrices`: a list of UB matrices checked and refined at every point.
  - `matrices_or_scratch`: the list of UB matrices first, indexing from scratch if they are rejected.
  - `redo_poor`: previous `.fit` files kept if they pass `ACCEPTANCE`, the others indexed again.
  - The previous results folder is archived as `<fit folder>_previous_<date>` when the indexation is run again.
- **Criteria of a correct solution** (`solution_criteria` of the indexing configuration, `SOLUTION_CRITERIA` and `MAX_PIXDEV` of the quickstart notebook). Steps `[e_max (keV), tolerance angle (deg), min nb of indexed spots]` are checked for every grain found, and grains failing them can be rejected.
- **Refinement steps** (`refinement_steps` of the indexing configuration and of the steps of a sequence, `REFINEMENT_STEPS` of the quickstart notebook). Steps `[e_max (keV), tolerance angle (deg), min nb of matches]`, with e_max increasing from the indexing energy while the tolerance decreases, are useful for low symmetry or large unit cells. `IB.refinement_ramp()` builds such a list.
- **Spots set A proposed for each image** (`central spots indices: zones`, `triplets` or `zones+triplets`): spots likely to have low Miller indices, as with the buttons of the Autoindexation board. Only pairs of proposed spots are then probed, so a small `nlutmax` such as 4 is enough.
- **Autoindexation board: *Stop* button.** A running indexation can be stopped, and the solutions found so far are kept (`indexingAnglesLUT.request_stop()`). The board stays responsive during the indexation.
- **Detector Calibration: rotation of the crystal around the axis of two spots.** Left-click two experimental spots (snapped to the nearest one) to define the axis q1 × q2, then drag with the right button to rotate the crystal around this axis.
- **Grains in depth (source of scattering displaced along the beam).**
  - `LaueGeometry.calc_uflab()` and `calc_xycam()` take the position of the source along the incoming beam (`offset`, mm, positive downstream).
  - `LaueGeometry.pixelshift_from_sourceoffset()` gives the exact X, Y shifts of the spots. The `depth` of `FitOrient` and of the plot/refine board is documented as the crude model it is: shift along pixel Y only, sample tilted by 40°, detector tilts neglected.
  - `tests/test_sourceoffset.py` checks the geometry against an independent ray tracing.
- **`LaueGeometry.peaklist_to_corfile()`** writes the `.cor` file of a peak list directly, and optionally its `.dat` file.
- **New quantities of the `.fit` files read by `fitfilereader`** (NaN for older files): equivalent (von Mises) strain, full and hydrostatic strain, lattice parameters from the full strain, and stress in the sample frame (assuming σzz = 0, in MPa).
- **`ipfmap`: monoclinic and triclinic crystals and pole figures.** It adds the colour keys and fundamental sectors of the Laue groups `2/m` and `-1`, `crystal_plane_normals()`, and `plot_pole_figures()` (stereographic projection in the sample frame).
- **Quick DAXM** (`Daxm/quickdaxm.py`, `daxm_workflow.py`, notebook `daxm/1_quick_daxm.ipynb` with `daxm/config_template.yaml`). It gives the depth of each Laue spot of a wire scan from the dips of its intensity profile, without reconstructing the images. Each dip edge gives the position of the source along the beam, using the wires trajectory of the `.calib` file. Results are written as a `.cor` file with a depth column and one `.cor` file per depth slice. It runs in the notebook, from the command line (`python -m LaueTools.daxm_workflow quickdaxm config.yaml --resource magnifix`) or as a job.
- **ROI counters workflow** (`scripts/workflows.py`, notebook `PixelMonitoring_Workflow.ipynb`):
  - `roicenters` can be a list of (X, Y) pixels, a peak list file (`.dat`, `.cor`, `.fit`, optionally limited to its first peaks: `{'file': path, 'maxnbrois': n}`) or an automatic grid (`{'grid': step}` or `{'grid': (stepX, stepY), 'xlim': ..., 'ylim': ...}`), see `resolve_roicenters()`.
  - `run_roi_counters_cached()` loads the results when they were already computed with the same parameters.
- **Plots of ROI counters maps** (`scripts/roicountersplot.py`):
  - `plot_counter_maps()` draws a grid of maps of one counter for several ROIs, with a shared zoom.
  - `CounterMapBrowser` is a browser of maps:
    - choice of ROI index, counter and value, contrast and log scale
    - zoom kept when browsing
    - image index, map position and value under the mouse
    - peak list on the detector: click a peak to show its map
    - ROI pixels of the clicked image
  - The sample y motor (yech, yps, ...) is always drawn vertically, whatever the fast and slow axes.
  - Zoom, hovering and clicks need `%matplotlib widget` (package `ipympl`).
- **SLURM jobs on several nodes** (`workflowlauncher`, new resource `magnifix3`, 3 nodes). One task per node processes a part of the images, and the parts are merged at the end of the job into the usual results file. By default whole nodes are used (all their cpus); `nbcpus` sets the number of cpus per node. Command line: `submit config.json --resource magnifix3 [--nodes N]`; the new commands `run --nbparts` and `merge` are used by the job. The `quickdaxm` workflow can also be launched by `workflowlauncher`.
- **PeakSearch GUI: scrollable pages.** The pages of both notebooks show scrollbars when the window is too small, so the GUI can be used on small screens.

### Fixes
- **DAXM point scans from BLISS hdf5 files:** the scan data were read only when `verbose` was set, and the wire motor (`yf` or `zf`) is now taken from the scan command.
- **`fitfilereader`:** UB matrices and lattice parameters written on several lines in the `.fit` file are read correctly.
- **Source offset in transmission and back-reflection geometries** (`calc_xycam_transmission()`, `calc_xycam_backreflection()`): the source is shifted along the incoming beam as in reflection geometry, and the sign of the distance correction is fixed. This is not yet validated on experimental data.
- **GTK file dialogs in a conda environment:** the *Recent* place was shown or not depending on how the session was started. The system GIO modules are now added, and a D-Bus session bus is started if there is none (`LAUETOOLS_NO_GTK_SETUP=1` to disable).
- The libtiff warning is no longer printed at import.
