## LaueTools 3.2.20 — Release notes

### ⚠️ Changes in behaviour
- **Number of cpus used on VISA, docker and SLURM.** The pools of processes of the notebooks, the GUIs, the peak search, the indexing and the workflows use `generaltools.available_cpus()`. It counts the cpus allocated to the process (SLURM, jupyter-slurm) and the cpu quota of its container. Before, on a VISA instance, the cpus of the whole host machine were used. Set `LAUETOOLS_NB_CPUS` (e.g. `export LAUETOOLS_NB_CPUS=8`) to choose the number. The PeakSearch GUI now uses all the cpus of a machine of up to 16 cpus by default.
- **Refinement of the lattice parameters in Detector Calibration starts from the current crystal.** The refined lattice parameters start from those of the current matrix UB.B0, with the lengths rescaled so that a length that is not refined keeps its value. The parameters that are not refined keep the values of the material. Before, the strain of UB (e.g. of an indexation) was absorbed by the refined parameters, which then differed from the lattice parameters written in the `.fit` file. The status bar lists the refined parameters.
- **New blocks in `.fit` files.** When the lattice parameters are given, the footer also contains `refined UB matrix` and `refined B0 matrix`. They give UB and B0 referred to the refined lattice parameters, to index other images with a new material that has these parameters: q = UB B0 G* = UB_new B0_new G*. They are read as `UB_new` and `B0_new` by `fitfilereader` and `orientationclustering`.
- **`IOLaueTools.readfitfile` returns a `fitfilereader.parsed_fitfile`.** There is now one parser for all the `.fit` file formats. The former class is kept as a name, for compatibility.
- **Unknown keys of the YAML configurations are reported.** A key that is not a parameter (e.g. a typo) is listed as a warning when the configuration is checked, with the closest valid key when there is one (`indexing_batch.unknown_keys()`).
- **Peak search rejects more badly fitted peaks** (`readmccd`, peak search GUI, `peaksearch_batch`, notebooks):
  - a peak is rejected when the fit does not determine its position (uncertainty infinite or larger than `FitPixelDev`). The uncertainties are now always computed;
  - a peak is too small when its *smallest* width is below the minimum size. Before, the largest width was used, and peaks of about one pixel in one direction were kept;
  - the widths of the fitted gaussians are written as positive values (their sign is meaningless).
- **Images with more local maxima than `NumberMaxofFits` are reported.** They are not fitted at all. They were reported as images "without peak". The peak search GUI, `peaksearch_batch` and its summary now give their number of local maxima and the value of `NumberMaxofFits` that would be needed (`readmccd.TooManyLocalMaximaError`, `PeakSearch(raise_too_many=True)`).
- **SLURM notebooks: magnifix jobs use whole nodes of 192 cpus.** ESRF IT accepts only jobs of 192 cpus per node on the magnifix partition. The resources of the launcher notebooks (indexing, mosaic, DAXM, `indexation/1b`, `1c`) were 96 cpus.

### New features
- **Rewrite of the strain of `.fit` files written before Oct. 2026** (`fitfile_strainfix.py`). The sample frame deviatoric strain of these files is wrong for hexagonal, trigonal, monoclinic and triclinic cells (fixed in 3.2.18).
  - The strain blocks are recomputed from the UB and B0 matrices of each file and written as by the current code: deviatoric strain in the crystal and sample frames, equivalent strain, full strain, hydrostatic strain and stress (σzz = 0).
  - The old sample frame strain of the file is kept in the `[TEMPORARY]` block, with its difference from the corrected one. The spots and the other blocks are copied unchanged.
  - `reference=` (`--reference Zr:Zr_ref`) gives the unstrained reference lattice instead of that of B0, e.g. a measured reference; `new lattice parameters` is then recomputed with the length a of the reference.
  - The elastic constants of a material such as `Zr_ref` are those of `Zr` (part of the name before `_`, or `stiffness_material=`).
  - Results are written in a `strainfix` subfolder by default (`--outputdir`, or `--inplace` to overwrite). Files already written with the corrected strain are skipped (`--force` to rewrite them).
  - Command line: `python -m LaueTools.fitfile_strainfix "<fit folder>/*_g*.fit" --reference Zr:Zr_ref`; from python: `rewrite_fitfiles_strain()`, `rewrite_fitfile_strain()`.
- **Indexing guided by neighbours: seeds** (`indexing_neighbours.py`, notebook `indexation/1d_index_refine_neighbours.ipynb`):
  - `seed_grid: none`: no grid, the seeds are those of `seed_images` only.
  - `seed_images`: image indices of seeds chosen by the user, added to those of the grid. `SeedPicker` adds them with the mouse on the plot of the seed grid (`%matplotlib widget`), and `update_seed_images()` writes them in the configuration.
  - `check_seeds()` checks UB matrices on the seeds and groups the seeds that have the same orientation. `seeds_from_fitfiles()` takes the UB matrices of `.fit` files, e.g. indexed with the GUI.
  - `merge_ub_matrices()` merges UB matrices closer than an angle, taking the crystal symmetry into account.
  - `ub_map_config()` and `plot_ub_maps()` check one UB matrix on all the images of the map and draw maps of the results, with hover and sliders.
- **Check of UB matrices on images** (`indexing_batch.test_ub_matrices()`): each UB matrix of `ub_matrices` on each `.cor` file, with the criteria of a correct solution and no `.fit` file written. `usepreviousUB: true` uses all the matrices of `ub_matrices`.
- **`indexing_batch.show_config()`**: pretty print of a configuration (nested sections, 3x3 matrices on 3 lines). Unknown keys are marked `!` and listed in red.
- **Faster indexing of a few images on many cpus.** When there are few images per cpu (e.g. seeds), the matching rates of each image are computed by its own pool of processes (`indexingAnglesLUT.set_internal_ncpus()`). A seed of NiMnGa indexed from scratch takes 58 s on 4 cpus instead of 115 s on 1.
- **Quickstart notebook: choice of the scans and of the configuration:**
  - `map_workflow.scan_filter()`: words of the dataset name (`'map2D -align'`: without "align"), scan names to include or exclude, prefix, only the scans ended with SUCCESS, minimum and maximum number of points, last scans.
  - `raw_data_folder()` gives the RAW_DATA folder of an experiment. `scan_index()` finds a map by its index or dataset name.
  - `find_configs()` and `ConfigSelector`: menu of the configuration files of the maps of an experiment, most recent first, with a filter. The menu of the maps also has a filter.
  - `refresh_done()` updates the column *done* of the table of the maps after new analyses, optionally by counting the result files.
  - `logfile_reader`: `node_filter` keeps only some scans of the `.h5` file while it is read.
- **Grains without indexation** (`grainimaging.find_grains()`, `plot_grains()`, `grains_table()`, `select_rois()`, section *grains without indexation* of the quickstart notebook). These functions find groups of ROIs (Laue spots) lit at the same map points: each group is a grain. They give its maps, its spots on the detector, a segmentation of the map and a table of the grains.
- **Maps of the results** (`LaueDataResultsPlots`): `LatticeParamMap()` (a, b, c, α, β or γ) and `StrainComponentMap()` (one deviatoric strain component). The mouse over a map shows the motor indices, the image index and the value (`generaltools.map_format_coord()`, `draw_map()`).
- **IPF color keys** (`ipfmap`): the mouse over the key shows the crystal direction, its color and the closest plane (hkl) and direction [uvw] (`nearest_lattice_vectors()`).
- **Detector Calibration:**
  - *Store U* button: stores the pure rotation U of the current matrix UB = U B (deviatoric strain removed), as the `Umatrix` of `.fit` files.
  - *show detector bands*: the bands without data (gaps between the modules) of EIGER 4M CdTe and sCMOS are drawn in light grey, in all the spaces (pixels, 2θ χ, gnomonic). Also in the plot/refine board (module `detectorbands.py`).
  - Selecting a link in the list of *Filter Links* marks its experimental spot and the simulated spot of the same hkl.
- **Manual indexation board:** sliders *Exp. spot size* and *power scale* (size = factor × (I/Imax)^power, power < 1 enlarges the weak spots). The same size and colour coding is used in all the spaces, with hollow markers over the background image.
- **`CrystalParameters.refined_UB_B0()`**: UB and B0 referred to new lattice parameters, with the scale and the rotation deviation.
- **SLURM resources:** the number of cpus of the nodes of a partition is read with `sinfo` when the job is submitted (`workflowlauncher.partition_nodecpus()`, `nodecpus` of a resource).
- **ROI counters read the whole image once from 20 ROIs** (`scripts/workflows.FULLIMAGE_MIN_ROIS`). Before, it did so only for EIGER detectors. With fewer ROIs, each ROI is still read in the file.
- **New materials** `NiMnGa_5M_exp` (4.26, 5.6266, 21.171 Å, β = 90.3°), `strained_NiMnGa_5M_exp`, `NiTi_martensite` (4.646, 4.108, 2.898 Å, β = 97.78°) and `NiTiB2` (3.015 Å, cubic).

### Fixes
- **`.fit` files written with numpy 2:** the detector parameters were written as `np.float64(...)`, which the `.fit` file readers could not read.
- **`fitfilereader` reads the `.fit` files of Detector Calibration** (table of the indexed spots with other columns).
- **Lattice parameter conversions with integer or list input:**
  - `CrystalParameters.dlat_to_rlat()` and `calc_epsp_cubic()` failed with integer lattice parameters, e.g. `dlat_to_rlat([5, 5, 5, 90, 90, 90])`.
  - `vol_cell()` (and `dlat_to_dil()`) failed with any python list, and modified the numpy array given as input.
  - The functions of the indexing, the GUIs and the `.fit` files always gave float arrays, so their results were not affected.
- **Peak fit uncertainties:** the X and Y uncertainties of the fitted positions (`XfitErr`, `YfitErr`) were swapped. A fit whose parameters are not determined now gives an infinite uncertainty instead of 0 (`fit2Dintensity.gaussfit()`).
- **Peak search GUI:** the columns of the fit errors were added again to the peak list at each peak search.
- **Maps:** figures whose layout cannot be computed are drawn as they are instead of raising an error. Titles and labels are plain text, which avoids the matplotlib mathtext error *exception raised in parse action* in some sessions.
- **Figures saved with `%matplotlib widget`** were sometimes partly transparent: they are now drawn with an Agg canvas.
- **Detector Calibration toolbar:** the *Flip up/down* button no longer moves into the overflow menu when the coordinates text grows.
- `readmccd` no longer prints `loading readmccd.py` at import.
