## LaueTools 3.2.17 — Release notes

### ⚠️ Changes in behaviour
- **Materials are now read from `materials.yaml`.** `dict_LaueTools.dict_Materials` is no longer the dictionary written in `dict_LaueTools.py` but a `Materials` object reading `materials.yaml` (`USE_MATERIALS_LIBRARY = True`). It is used like a dictionary: `dict_Materials['Ge']` still returns `['Ge', [a, b, c, alpha, beta, gamma], 'dia']`. `materials.yaml` contains all the materials of the former dictionary. `dict_Materials[label] = [...]` adds a material for the current session only: use `add_or_update_material()` or the materials editor to save it.
- **Your own materials and settings are in `~/.lauetools`.** When LaueTools is installed with `pip` (not a git clone or `pip install -e`), a material you add is written in `~/.lauetools/materials.yaml`, which is then read instead of the installed file and is kept when LaueTools is upgraded. Materials added to the installed file by a later release are not added to your copy. `lauetools_config.json` is also written in `~/.lauetools` (the one in the LaueTools folder is still read). Set the environment variable `LAUETOOLS_USER_DIR` to use another folder.
- **`lauetools-copy-materials` keeps an existing `materials.yaml`** in the destination folder. Use `--force` to overwrite it.
- **`NBMAXPROBED` is renamed `MAXINDEXPROBED`** (largest index of the spots of set B, included). The meaning is unchanged and `NBMAXPROBED` is still accepted in dictionaries, `.irp` files and YAML configurations.
- **Detector Calibration: modified lattice parameters are no longer saved in `materials.yaml` by default.** The material `strained_<material>` created by the +/− buttons, a typed value or a refinement is kept until LaueTools is closed. Check *Save created materials in materials.yaml* to save it.
- **Detector Calibration `.fit` file with a strained material.** When the current material is `strained_<material>`, the file is written with respect to the unstrained material: `Element` is `<material>`, and the UB and B0 matrices are those of this material (the UBB0 matrix is unchanged).
- **Older tutorial notebooks are anonymized.** Data paths, proposal numbers and host names of `Basic_PeakSearch_IndexRefine`, `Indexation_MultiProcessing`, `Indexation_MultiProcessing_april2025`, `Indexation_MultiProcessing-Tutorials`, `indexing_mpi_slurm_launcher` and `strainrefinementdistribution_depthimpact` are replaced by placeholders such as `<proposal>` or `<inhouse path>`: set your own paths before running them.

### New features
- **Materials editor.** New window (menu *Indexation → Materials Editor* of the main GUI, or the command `lauetools-materials`) showing the materials in a table that can be sorted by name, a, b, c, alpha, beta, gamma or extinction (click on a column title, click again for the reverse order), with a filter on the first letters of the name. A form adds, updates or deletes a material; lattice parameters accept expressions such as `5.982*5.05/5`.
- **Material menus shrink while typing.** In the simulator, autoindexation, manual indexation, plot/refine, detector calibration and cliques boards, typing the first letters of a material shrinks the list to the materials starting with these letters (whatever the case). Enter or leaving the field selects the material.
- **Refresh button next to the material menus.** It reads `materials.yaml` again if it has been modified by another program, for example the materials editor running at the same time. Both programs can save materials without losing those of the other one.
- **Detector Calibration: refinement of lattice parameters.** Each of a, b, c, alpha, beta, gamma has a *fit* check box in the lattice parameters tab. Checked parameters are refined together with the checked detector parameters and orientation angles. a, b and c cannot be refined together, because Laue spots positions do not depend on the unit cell volume. No symmetry constraint is applied. Detector and lattice parameters are strongly correlated: refine lattice parameters with detector parameters fixed from a reference crystal. New functions `FitOrient.error_function_calibration_latticeparameters()` and `FitOrient.fit_calibration_latticeparameters()`.
- **Detector Calibration `.fit` file: lattice parameters and strain.** The file now contains the lattice parameters of the crystal, the deviatoric strain in crystal and sample frames, the equivalent strain and the name of the unstrained reference material, as the `.fit` files of plot/refine and `indexingSpotsSet`.
- **Indexing by a sequence of steps** (`indexing_sequence.py`, section `sequence:` of the YAML configuration): several materials or a substrate indexed one after the other on the spots not yet indexed, each step with its own parameters and acceptance criteria. New notebooks `indexation/1b_index_refine_substrate.ipynb` and `indexation/1c_index_refine_multimaterials.ipynb`.
- **Blacklisted spots.** `blacklist` and `blacklist_tolerance` of the YAML configuration remove given spots (for example those of a substrate, from a `.cor`, `.dat` or `.fit` file or a list of pixel positions) from each `.cor` file before indexing.
- **Proposal of central spots** (`spotsproposal.py`): spots likely to have low Miller indices, ranked by the number of zone axes or of recognised triplets. Buttons *Zones intersects*, *Triplets* and *Merge* in the autoindexation board fill spots set A.
- **Spots sets.** Spots set A accepts `'to12'` (0 to 12), `'80to90'`, python slices and lists; spots set B can be given explicitly with `spots set B` instead of `MAXINDEXPROBED`.
- **Index_Refine board** can run the `indexing_batch` engine: the parameters of the board and of the `.irp` file are written in a YAML configuration.
- **Cliques board:** the material of the angles look-up table is chosen in a list.
- **New functions for peak lists:** `IOLaueTools.getspotsproperties_byname()` and `IOLaueTools.peaklistarray_from_spotsproperties()` read spots properties by column name; `dict_LaueTools.reload_materials()` and `Materials.reload()` read the materials file again when it has been modified.

### Fixes
- **`materials.yaml` was missing from the pip package:** the materials library and `lauetools-copy-materials` could not work after `pip install`.
- **`Materials()` failed without `lauetools_config.json`,** and `Materials.read_yaml(path)` ignored the given file (*Reload Materials* with a YAML file loaded another file).
- **Lattice parameters written as expressions in `materials.yaml`** (for example `'4.225*1.04'`) were kept as text instead of numbers.
- **Detector Calibration: peak lists with any number of columns.** A `.cor` file with 15 columns (`nbcolumns =15 is higher than 13! ... Not implemented yet!`) or without `Xfiterr` and `Yfiterr` could not be used. Spots properties are now read by column name, and missing ones are set to 0.
- **Detector Calibration: fit with a `.cor` peak list** failed when the `.cor` file was written again at the end of the fit (`Compute_data2thetachi`).
- **Detector Calibration:** cancelling the dialog of the `.fit` file name raised an error.
- **Autoindexation board:** the *Refresh* button added a second material menu instead of updating the list.
- **Cliques search with networkx 3 or later** (`cliques_containing_node` has been removed from networkx).

### Packaging
- **New package data:** `materials.yaml`.
- **New command `lauetools-materials`** (materials editor, without terminal window on Windows).
